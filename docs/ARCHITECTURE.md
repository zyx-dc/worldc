# WorldSource · 内容空间编译器

> 你的收藏夹不需要一个生成器。它需要一个编译器。

---

## 1. 先说清楚我们要反对什么

现在所有「AI + 内容 → 空间」的做法都是同一条流水线：

```
prompt → LLM 直接吐 JSON / three.js 代码 → 一次性渲染 → 录屏
```

它有三个绕不过去的死穴，而且都不是工程问题，是**范式问题**：

| 死穴 | 表现 | 后果 |
|---|---|---|
| **不可复现** | 同一份收藏夹，今天生成一个房间，明天生成另一个 | 没法做产品，只能做 demo |
| **不可编辑** | 想挪一件东西，只能整段重新生成，其它全变 | 用户永远无法"拥有"这个世界 |
| **不可比较** | 无法回答"这一年我的收藏夹发生了什么变化" | 最动人的叙事直接消失 |

第二条尤其致命：**观众一旦发现自己不能改，他就只是观众。** 这个比赛要的是"观众即用户"。

---

## 2. 核心命题

**把 3D 场景从「作品」降级为「编译产物」，把一份纯文本的 `.world` 源文件提升为唯一真相。**

```
.world 源文件  ──编译──▶  IR（场景图）  ──渲染──▶  3D 漫游 / 2D 导览图
   唯一真相                 可寻址中间产物            多个后端
```

这不是换了个说法。它一次性解决了上面三个死穴：

- **可复现** ← 源文件里写的是种子，不是坐标
- **可编辑** ← 覆盖层（pin）是源文件的一部分，改一行就是改一处
- **可比较** ← 两次编译的 IR 可以做 diff，差异就是内容

---

## 3. 分层架构

```
L1  摄取        B站公开收藏夹  |  本地相册  |  Mock
                     ↓  适配器模式，输出结构统一
L2  归一        Item { id, title, cover, year, owner }
                     ↓
L3  理解        本地嵌入 → 聚类 → 命名
                     ↓  ★ LLM 的职权被限制在"命名"这一个自由度上
L4  世界源      .world  =  规则 + seed + 稀疏覆盖        ← 唯一真相
                     ↓
L5  编译        纯函数 → IR（场景图）· region 级缓存 · 内容寻址
                     ↓
L6  渲染        IR ─┬─▶ 3D 漫游（three.js）
                    └─▶ 2D 导览图（SVG / Canvas）
```

**目录对应：**

| 层 | 文件 |
|---|---|
| L1 | `src/adapters/bilibili.mjs`（真实）· `src/adapters/mock.mjs`（离线） |
| L2 | 适配器输出即为归一结构 |
| L3 | `src/naming.mjs`（命名）· 嵌入聚类待接 |
| L4 | `examples/*.world` · `spec/world.dsl.md` · `src/importer.mjs` |
| L5 | `src/parse.mjs` → `src/layout.mjs` → `src/compile.mjs` |
| L6 | `viewer/`（3D）· `src/render/plan.mjs`（2D） |

> **L3 的现状要说清楚**：嵌入聚类还没接，目前是「按时间分块 + 关键词命名」。
> 命名层已经是可插拔的（`keyword` / `llm` 两个策略），换成真正的模型只需要实现
> `llmName()`，编译器一行都不用动。这恰好验证了"AI 权限最小化"这个设计是站得住的
> —— 把最不确定的一步做成一个可替换的小接口，骨架就永远是确定的。

## 4. 四个设计决策

每一条都有对应的可执行验证（`node test/determinism.mjs`，7/7 通过）。

### D1 · 写种子，不写坐标

源文件里**没有一行坐标**。展品位置是纯函数：

```
pos = f(seed, region 规则, item id)
```

`rng.mjs` 里没有任何 `Math.random()`，只有 mulberry32 + FNV-1a。每件展品用**独立的随机流**（以 `seed+region+id` 为种子），所以新增一件收藏不会挪动其它任何一件。

> **实测**：同一份源文件编译两次，`sha256` 完全一致（`f02df125…`）；换一个 seed，120 件全部换位。

**为什么这是产品级而不是炫技**：用户三年后换台电脑打开，还是那个房间。这一条本身就是可以写进宣传语的产品承诺。

### D2 · 推导层 + 覆盖层

源文件里 120 件展品只占 37 行。位置是推导出来的，**只有用户亲手挪过的那件，才会被写进 `pin`**。

```
pin item:42 at -3.2 0 -1.5 rot 30
```

这是 CSS 层叠、Terraform state、游戏编辑器 "procedural + overrides" 的同一个思想，但它在这里的作用是：**让「生成」和「编辑」不再互斥**。

> **实测**：给 120 件的世界加 2 个 pin，空间 diff 报 `moved 2`，其余 118 件一寸未动。

**这是双向编辑的地基**：在 3D 里拖动一件 → 往源文件里写一行 pin → 重新编译。反过来改文本也一样。

这条现在已经真的跑通了（`?edit=1`，实测用 CDP 驱动真实页面）：

```
拖动前  39 行 · 0 条 pin · 5 号展品在 [8.349, 0, -6.731]
拖动后  40 行 · 1 条 pin · "pin item:5 at 3.5 0 -2 rot 42"
        5 号展品实际位置 → [3.5, 0, -2] · pinned=true
```

**为了让这条成立，编译器必须同构。** `src/hash.mjs` 用纯 JS 重新实现了 sha256
（已和 `node:crypto` 逐位比对一致），否则浏览器里算出的 hash 和 Node 不一样，
"改文本→重建"就只是动画，不是真的编译。这是架构约束，不是实现细节。

### D3 · 世界是程序，不是资产

整个房间没有模型文件、没有贴图包、没有烘焙光照。只有一份几百字节的源文件和一批封面图 URL。

> **实测**：37 行 / 0.7 KB 源文件 → 120 件展品 → **14.2 KB 空间图**，编译 4.4 ms。

直接后果：
- 世界可以通过链接传给别人（发送的不是场景，是源文件）
- 可以在手机上跑
- **可以完全离线跑** —— 这是 NVIDIA「RTX Spark 本地 AI 单元」的正面战场

### D4 · 空间 diff 是一等公民

因为编译是确定性 + 内容寻址的，"两个世界之间发生了什么"是可以精确计算的：

```
worldc diff a.world b.world
  moved   2 件
  gone    0 件
  added   0 件
          #77  深夜补番        位移 4.844
```

> 这一条撑起的是整个内容叙事里最动人的一集：**「git diff for space」** —— 不是并排两张截图，而是一面墙在两年里怎么长高、哪个房间被清空了。

**同一份 IR，两个渲染后端**（3D 漫游 / 2D 导览图）不是为了好看，是为了证明这真的是一层 IR，而不是 three.js 的包装。2D 后端顺带产出传播素材 —— 每个世界的导览图就是它的封面。

## 5. 哪里是借的，哪一点是原创

**我不打算假装全是新的。** 这套架构的每个零件都有出处：

| 零件 | 出处 |
|---|---|
| 种子 → 确定性生成 | Minecraft |
| 推导 + 覆盖（single source of truth） | Terraform / CSS 层叠 / 游戏编辑器 |
| 源文件 → IR → 多后端 | 编译器（LLVM 的经典结构） |
| 世界 diff | Git |

**真正原创的，只有一句设计立场：**

> **把 LLM 的职权下降到「只负责命名」。**

现在所有 AI 生成 3D 的做法都是让 LLM 直接吐结构和坐标。那是把不可复现的源头放在了最核心的位置。我们的做法是：**结构由确定性规则产生，LLM 只给区域起名字**（"前端考古"、"调参玄学"、"AI 元年"）。

这个约束换来两件事：
1. 世界的**骨架**永远可复现，AI 的不确定性被关在一个不影响几何的盒子里
2. 命名恰恰是 LLM 最擅长、也最打动人的部分 —— 它不画房间，但它知道这堆视频叫什么

我会把这条叫 **AI 权限最小化（least-privilege generation）**。它既是工程决策，也是一句很好的视频标题。

## 6. 为什么这套架构天生适合这个比赛

回到赛制：前 30 名由 AI 按视频表现数据筛，决赛由用户评审团投票。也就是说 —— **架构必须能变成画面。**

这套东西的每一层都能单独拍一集，而且**不需要露脸**：

| 集 | 画面 | 架构层 |
|---|---|---|
| 1 | `worldc build` 的编译日志一行行刷出来，最后吐出 hash | L5 |
| 2 | 第一次走进世界，撞墙（保留翻车） | L6 |
| 3 | 鼠标停在展品上浮出展签 | L3 |
| 4 | 左边改一行源文件，右边世界重建 | D2 |
| 5 | **拔掉网线**，本地相册版继续跑 | D3 |
| 6 | 两个版本的空间 diff，墙在原地长高 | D4 |
| 7 | 50 个观众的世界同时编译，服务器挂掉 | 规模化 |
| 8 | 年度导览图（2D 后端） | 双后端 |

另外一个副产品：**对一个不出镜的创作者来说，CLI 是完美的主角。** `worldc build` 的编译日志本身就是电影里"黑客在敲键盘"的那个画面，而且它全部是真实的。

## 7. MVP 边界

必须先说清楚：这套东西比"一次性生成"重。所以按集切，每一集都有可交付物。

| 版本 | 范围 | 对应集 | 状态 |
|---|---|---|---|
| **V0** | L1(mock) + L4 + L5 + 验证 | 集 1 | ✅ 已完成 |
| **V1** | three.js 渲染 IR + 第一人称漫游 | 集 1-2 | ✅ 已完成 |
| **V1b** | 2D 导览图后端（SVG） | 集 8 | ✅ 已完成 |
| **V2** | 接入 B站公开收藏夹适配器 | 集 2-3 | ✅ 已完成（另含自动命名 + 真实封面） |
| **V3** | pin 的双向编辑（拖动 → 写回源文件）+ 编辑器 | 集 4 | ✅ 已完成 |
| **V4** | 本地相册适配器 + 离线打包 | 集 5 | NVIDIA 单元报名 |
| **V5** | 空间 diff 可视化 | 集 6 | |
| **V6** | 真实封面图（替换程序化贴图） | 集 2 | |

**刻意不做**：多人实时协作、3D 重建、物理引擎。都不是这个故事的必需品。

## 8. 风险

| 风险 | 判断 | 对策 |
|---|---|---|
| **B站公开收藏夹是否可读** | 地基。若不成立，整个 L1 塌方 | **动工前用十分钟验证**；备选：让用户手动导入 JSON |
| 聚类质量差 → 世界看起来乱 | 中 | 兜底布局按时间轴分层，永远不难看 |
| three.js 里做拖拽 + 写回 | 中高 | V3 才做，V1 先只读 |
| "架构太硬核，观众看不懂" | 中 | 每集只讲一个决策，配一个动作。不讲原理，讲它解决什么问题 |

## 9. 一句话总结

> 别人在做「AI 生成一个房间」，我们在做**「一趟编译器」**。
> 生成的房间只能用一次，编译出来的世界可以养。
